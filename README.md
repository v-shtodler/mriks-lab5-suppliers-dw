# ЛР5 МРІКС — сховище даних «Надійні постачальники»

Командна лабораторна робота №5 з дисципліни «Моделювання та розроблення ІКС»: проєктування багатовимірного сховища даних.

**Що вирішує сховище:** допомагає відділу закупівель зрозуміти, які постачальники сировини надійні — возять вчасно, у повному обсязі й без браку, — а від яких підприємство ризиковано залежить.

**Предметна область:** закупівля сировини й матеріалів (фанера, фарби, пакування) на умовному підприємстві, що виробляє дерев'яний настінний декор.

**СУБД:** PostgreSQL. **Схема:** «зірка» — 1 таблиця фактів і 5 вимірів.

## Команда

| Роль | Учасник | Зона відповідальності |
|---|---|---|
| Архітектор даних | _вписати_ | Схема сховища, факти й виміри, діаграма |
| Інженер даних | _вписати_ | DDL-скрипт, розгортання в PostgreSQL, репозиторій |
| Аналітик / тестувальник | _вписати_ | Аналітичні задачі й запити, тестові дані, рецензування |

## Як розгорнути

```bash
createdb suppliers_dw
psql -d suppliers_dw -f sql/ddl/01_create_dw.sql      # структура
psql -d suppliers_dw -f sql/dml/02_sample_data.sql    # тестові дані (необов'язково)
psql -d suppliers_dw -f sql/tests/03_integrity_checks.sql  # тести цілісності, скрізь має бути 0
psql -d suppliers_dw -f sql/queries/analytics.sql     # запити
```

## Як ми працюємо

1. Кожна задача — це Issue з виконавцем і дедлайном на дошці проєкту.
2. Зміни робимо в окремій гілці й відкриваємо Pull Request.
3. Структуру сховища зберігаємо як код: будь-яка зміна таблиць — це зміна DDL-скрипту в репозиторії («схема як код»).
4. PR перевіряє інший учасник за `docs/04_review_checklist.md`, після схвалення — merge у `main`.
