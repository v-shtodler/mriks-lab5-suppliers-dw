# 2. Схема сховища

## Чому «зірка»

Обрано схему «зірка»: таблиця фактів у центрі, навколо неї виміри.

- Вона проста: кожен вимір — одна таблиця.
- Запити короткі: з'єднуємо факти з потрібним виміром і рахуємо.
- Довідники в нас малі, тому ділити їх на менші таблиці («сніжинка») немає сенсу.

## Таблиця фактів `fact_supply`

Один рядок — це одна поставка одного матеріалу.

| Поле | Тип | Що означає | Категорія |
|---|---|---|---|
| `supply_key` | INTEGER | номер поставки | первинний ключ |
| `date_key` | INTEGER | дата поставки | зовнішній ключ |
| `supplier_key` | INTEGER | постачальник | зовнішній ключ |
| `material_key` | INTEGER | матеріал | зовнішній ключ |
| `warehouse_key` | INTEGER | склад | зовнішній ключ |
| `qty_ordered` | NUMERIC(10,2) | замовлено | адитивна міра |
| `qty_delivered` | NUMERIC(10,2) | привезено | адитивна міра |
| `qty_defective` | NUMERIC(10,2) | брак | адитивна міра |
| `unit_price` | NUMERIC(10,2) | ціна за одиницю | неадитивна міра |
| `amount` | NUMERIC(12,2) | сума, грн | адитивна міра |
| `delay_days` | INTEGER | запізнення, днів (0 = вчасно) | адитивна міра |

Адитивну міру можна додавати (кількість, сума). Неадитивну додавати не можна (ціна).

## Виміри

| Таблиця | Що описує | Поля |
|---|---|---|
| `dim_date` | період | дата, місяць, квартал, рік |
| `dim_supplier` | постачальник | назва, тип, місто |
| `dim_material` | матеріал | назва, група, одиниця виміру |
| `dim_warehouse` | склад | назва, місто |
