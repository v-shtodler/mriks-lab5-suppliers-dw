# 2. Проєкт сховища даних

## Чому «зірка», а не «сніжинка»

Обрано схему **«зірка»**: одна таблиця фактів у центрі й виміри навколо, кожен вимір — одна таблиця.

- **Запити простіші.** Щоб порахувати показник у будь-якому розрізі, достатньо одного `JOIN` на вимір.
- **Виміри невеликі.** Постачальників десятки, матеріалів сотні. Якщо винести країну чи групу матеріалу в окремі таблиці, місця заощадимо мало, а запити ускладняться.
- **Зручно для BI.** Power BI та подібні інструменти найкраще працюють саме із «зіркою».

«Сніжинка» мала б сенс, якби ієрархії були великими й часто змінювались (наприклад, детальний географічний довідник). Тоді з `dim_supplier` можна винести таблиці `dim_region` і `dim_country`, а з `dim_material` — `dim_material_group`.

## Зернистість таблиці фактів

Один рядок `fact_supply` = **одна позиція замовлення постачальнику** (один матеріал в одній поставці). Дрібніше дані не потрібні, а з такого рівня можна зібрати будь-які підсумки.

## Таблиця фактів `fact_supply`

| Поле | Тип | Призначення | Категорія |
|---|---|---|---|
| `supply_key` | BIGSERIAL | первинний ключ | — |
| `order_date_key` | INTEGER | дата замовлення → `dim_date` | зовнішній ключ |
| `promised_date_key` | INTEGER | обіцяна дата поставки → `dim_date` | зовнішній ключ |
| `delivery_date_key` | INTEGER | фактична дата поставки → `dim_date` | зовнішній ключ |
| `supplier_key` | INTEGER | постачальник → `dim_supplier` | зовнішній ключ |
| `material_key` | INTEGER | матеріал → `dim_material` | зовнішній ключ |
| `warehouse_key` | INTEGER | склад → `dim_warehouse` | зовнішній ключ |
| `buyer_key` | INTEGER | менеджер → `dim_buyer` | зовнішній ключ |
| `po_number` | VARCHAR(30) | номер замовлення | вироджений вимір |
| `qty_ordered` | NUMERIC(12,2) | замовлена кількість | адитивна міра |
| `qty_delivered` | NUMERIC(12,2) | привезена кількість | адитивна міра |
| `qty_defective` | NUMERIC(12,2) | кількість браку | адитивна міра |
| `amount` | NUMERIC(14,2) | сума поставки, грн | адитивна міра |
| `delay_days` | INTEGER | запізнення в днях (≤ 0 — вчасно) | адитивна міра |
| `unit_price` | NUMERIC(12,2) | ціна за одиницю | неадитивна міра |
| `is_on_time` | BOOLEAN | поставка вчасна | ознака (рахуємо частку) |
| `is_complete` | BOOLEAN | поставка повна | ознака (рахуємо частку) |
| `has_claim` | BOOLEAN | була рекламація | ознака (рахуємо кількість) |

**Категорії мір простими словами:**

- *адитивна* — можна сумувати в будь-якому розрізі (кількість, сума);
- *неадитивна* — сумувати не можна, тільки середнє чи перерахунок (ціна, відсотки);
- *напівадитивних* мір (як залишок на складі, який не сумують у часі) у цій моделі немає.

Вимір дати використано тричі в різних ролях (замовлення, обіцянка, факт) — це називають рольовим виміром.

## Таблиці вимірів

### `dim_date` — «Період»

| Поле | Тип | Призначення |
|---|---|---|
| `date_key` | INTEGER, PK | дата у форматі РРРРММДД |
| `full_date` | DATE | календарна дата |
| `day_of_month`, `day_of_week`, `week_of_year` | SMALLINT | день місяця, день тижня, тиждень |
| `month_num`, `month_name` | SMALLINT, VARCHAR(20) | місяць |
| `quarter_num`, `year_num` | SMALLINT | квартал, рік |
| `is_weekend` | BOOLEAN | вихідний |

### `dim_supplier` — «Постачальник»

| Поле | Тип | Призначення |
|---|---|---|
| `supplier_key` | SERIAL, PK | сурогатний ключ |
| `supplier_code` | VARCHAR(20) | код з облікової системи |
| `supplier_name` | VARCHAR(150) | назва |
| `supplier_type` | VARCHAR(30) | виробник / дистриб'ютор / імпортер |
| `country`, `region`, `city` | VARCHAR | географія |
| `payment_terms_days` | SMALLINT | відстрочка платежу, днів |
| `contract_start` | DATE | початок співпраці |
| `is_certified` | BOOLEAN | є сертифікат якості |
| `is_active` | BOOLEAN | чинний постачальник |

### `dim_material` — «Матеріал»

| Поле | Тип | Призначення |
|---|---|---|
| `material_key` | SERIAL, PK | сурогатний ключ |
| `material_code` | VARCHAR(20) | код матеріалу |
| `material_name` | VARCHAR(150) | назва |
| `material_group` | VARCHAR(60) | група (фанера, фарби і лаки, пакування, кріплення) |
| `unit_of_measure` | VARCHAR(10) | одиниця виміру |
| `is_critical` | BOOLEAN | критичний для виробництва |

### `dim_warehouse` — «Склад»

| Поле | Тип | Призначення |
|---|---|---|
| `warehouse_key` | SERIAL, PK | сурогатний ключ |
| `warehouse_code` | VARCHAR(20) | код складу |
| `warehouse_name` | VARCHAR(100) | назва |
| `city` | VARCHAR(80) | місто |

### `dim_buyer` — «Менеджер із закупівель»

| Поле | Тип | Призначення |
|---|---|---|
| `buyer_key` | SERIAL, PK | сурогатний ключ |
| `buyer_code` | VARCHAR(20) | табельний код |
| `full_name` | VARCHAR(120) | ПІБ |
| `department` | VARCHAR(80) | відділ |
